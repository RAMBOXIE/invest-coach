# 形态重构提案 · v1（待讨论确认）

> **缘起**：owner 2026-08-25 的批评——「LLM 教练没有感知，没有充分利用 LLM 的能力，只有选择题不符合 LLM 的第一性原理……现在的形式只是换了题材的多邻国，和 AI Native 的学习方式目标不一致。」
> **依据**：9 路研究（LLM 辅导 RCT / 产品扫描 / 教学法 / 自由作答评估 / 动态生成可靠性 / 展示与成本 + 3 路对抗）。全部结论带外部证据。
> **状态**：提案，**未实施**。§7 是需要 owner 裁决的清单。

---

## 1. 结论先行

**批评成立，而且文献里有它的精确对应物与量化差距。** 智能辅导系统的元分析把辅导分成两档：`answer-based`（只判最终答案对错）**d≈0.31**，`step-based`（对推理的每一步给反馈）**d≈0.76**（VanLehn 2011，54 组对比）。**我们现在做的是标准的 answer-based**——学习者点一个选项，规则引擎判对错。「换了题材的多邻国」在文献里的名字叫 answer-based tutoring，差距约 **0.45 SD**。

**但「改成自由对话」是被 RCT 直接证伪的解法。** 三条独立证据：

| 证据 | 结果 |
|---|---|
| Bastani et al., **PNAS 2025**（土耳其高中约 1,000 人，三臂 RCT） | 自由用 GPT 组练习表现 **+48%**，撤走 AI 后考试 **−17%**（低于从未用过 AI 的对照）。加了教学护栏的 GPT Tutor 组练习 **+127%**，考试与对照**无差异** |
| Oreopoulos & Low, **NBER w35620**（田纳西 18 校，两学年整群 RCT） | Khanmigo（已按「只教练不给答案」配置）效应 **0.06–0.08 SD/学年**，**与不带 AI 的结构化练习相当**。行为数据：中位学生只在 **1/3 的练习日**发过消息，只在 **17%** 的「刚答错」时刻用它 |
| Fan & Gašević, **BJET 2025**（n=117 随机分组） | ChatGPT 组**作品分数显著提升**，但**知识获得与迁移无显著差异**——作者称之为「元认知懒惰」 |

产品侧同向：Quizlet Q-Chat 下线、Google Socratic 并入 Lens、Sizzle 被并购、Duolingo 考虑砍掉 Max、AllHere 上线 3 个月关停。**纯聊天框在消费级学习产品里没有跑通的先例**；唯一像样的案例（CS50 Duck，20 万用户）成立条件是「上下文自动注入 + AI 拿不到评分权 + 嵌在强动机课程里」。

**唯一赢过课堂的 LLM 辅导 RCT，赢的那个不是聊天框**：Kestin et al., Scientific Reports 2025（哈佛 PS2，n=194 随机交叉）拿到 0.63–1.3 SD，但那个 tutor 是**预写分步解法注入 prompt + 强制一次一步 + 禁止跳序 + 禁止直给答案**的脚本化流程。

> **两句话总结**：LLM 的收益来自**被约束的引导**，不来自**更大的自由度**。所以正确的重构不是「把选择题换成对话」，而是**「从 answer-based 升级到 step-based，由 LLM 承担步级反馈」**——这恰恰需要 LLM 的推理与语义分析，是 owner 想要的东西，只是入口不是输入框。

## 2. 一个我必须先承认的错误：契约漂移

契约审查查出：**「判分永远是规则引擎，LLM 永不判分」不是 owner 的原始裁决，是我造成的漂移。**

- v3 §2.6 的逐字原文是：「深度判卷层（完整决策陈述 + LLM 全 rubric 判卷）**推迟**」，理由是**商业先例**（一个 C 端产品同时装高频微题层与低频深度层无跑通先例，反例成链）——**不是**「LLM 判卷不可靠」。
- 同一份 v3 的 §5 裁决表第 6 行已经裁过：「LLM 判卷**能**撑对外分数，但需锚定样例 + 校准集、rubric 压到 2–3 档、每维单独调用、置信门控转人工、不做排名」。
- 「跨用户 rank-order 一致性近零」在 v3 里是 §2.5 用来**否决排行榜**的（排行榜本就不做）。

是我在四份派生文档里把「推迟」硬化成了「永久禁区」并记在 §2.6 名下。**所以这次不是「要不要破契约」，而是「回到契约原文，并补上 §5#6 早就写好的条件」。**

不过——**即便可以放开，我仍建议判分留在规则引擎**，理由是新的、当初没有的证据：LLM 评分在**部分正确**的中段显著退化（全对/全错很准，中段塌陷），而学习者 90% 的时间都在部分正确里；且按人群的带内偏移达 +0.55~−0.34 SD（有方向的不公平，不是噪声）。

## 3. 提案的核心：把每道题从「一拍」改成「三拍」

现在：`看材料 → 点选项 → 判分 → 下一屏`
提案：`看材料 → ①先写 → ②收束 → ③诊断与追问 → 锚题点亮`

### ① 先写（不判分）
材料给完，**先出一个空白框**：「用一两句话说：你觉得这家公司可疑吗？凭什么？」写完（或点「我想不出来」）才展开选项。

- 收益不需要任何判分就能拿到：自我解释元分析 **g=0.55**（64 份报告）；先猜后学配纠正反馈优于无错学习。
- **顺手治好一个已存在的病**：现在的选项本身泄题。看 `rf1-q2` 的正确选项——「信息不足，无法判断——先按备考口径剔除并表影响重算」，把答案连解法一起送到了学习者眼前。先写后对照直接消除这个泄漏。
- **第一版可以完全不接 LLM**（文本只存本地），当天就能上线。

### ② 收束（规则引擎判分，一切现有指标不动）
结论三选 + 信心三档 + **证据卡片选择/排序**（从材料里挑出你依据的那几行，排出推理顺序）。判分仍是规则引擎，Brier 校准分、85% 答对率锚、混淆对误伤率、HLR 复训调度**全部照旧可算**。

证据卡片是把「自由作答的诊断丰富度」和「客观可判分」同时拿到的成熟做法（有序多选 OMC：卡片文本取自真实学习者的开放作答，每张卡映射一个已知误解层级或正典条目 id）。

### ③ 诊断与追问（LLM 的主场，这一步才是 AI-native）
LLM 读学习者在 ① 写的那段话，**输出只能是闭集 JSON**：

```
{ spans: [学习者原文的字符区间],
  labels: [来自本题预置误解库的 enum id],
  missing_canon_ids: [本题正典要点中未被提及的],
  confidence: high|medium|low }
```

- **LLM 不写反馈正文**——它只决定「展示哪一条已人工签字的静态文案」。现有的「用户可见文本必须逐条签字 + hash 绑定」契约**零修改即满足**，也顺带杜绝了运行时幻觉数字。
- 标签 → 分数的映射由规则引擎查表；且标签**只进错题档案与复训队列**（低风险个性化），**不进校准分、不进任何跨用户比较**。
- 之后开放追问，**教练可以问你任何问题，但它的每一个陈述句都必须能指回一条已签字材料**（体裁限定为：提问 / 复述已注入材料 / 指向第 N 屏或某条 canon）。
- **误解库必须题目级、封闭、每题 3–7 条**——这是成败分水岭，证据很干净：题目级小标签集的开放作答分类准确率可达 0.94+，而全局大标签池（2,500+ 条）只有 0.5–0.6。这个人工成本必须认。

### 锚题：戳破学习错觉的唯一机制
**无论聊多少轮，节点点亮的唯一条件是通过一道闭卷、规则判分、对话中从未出现过的迁移题。**

这是本提案里最重要的一条机制，理由直接来自 Bastani 的方法论教训：**练习期 +127% 与考试 ±0% 可以同时成立**。没有这个口径，任何 LLM 改版都无法证明自己不是第二个 GPT Base 组。配套：复训回合一律**禁用问教练**，AI-off 复训正确率与 Brier 校准分作为主指标；对话时长、轮数、满意度**降级为诊断指标，永不作为北极星**（学习感与实际学习系统性反向）。

## 4. 「教练没有感知」的最低成本解（建议第 0 步，先做）

这一条根本不是交互形态问题，是**管道问题**：系统已经有错题档案、混淆对、信心档、提示层级、校准分、复训到期表——**只是从没注入过 prompt**。

把这些状态塞进教练的 system prompt，「无感知教练」立刻变成「有感知教练」：零新形态、零新契约、一天工作量。

且触发要**系统主动**，不要摆一个「有问题问我」的框等用户开口（Khanmigo 数据：给了自由入口，中位学生 2/3 的日子根本不用）。触发条件写死在规则里：连续两次踩同一混淆对 / 高信心答错（过度自信正是校准分要治的病）/ 某屏停留异常久 / 复训二次失败。

## 5. 「动态生成新场景」怎么做而不毁掉溯源

主轴是一条本次研究提炼出的新区分：**LLM 有组合权，没有生成权。**

| 层 | 内容 | LLM 权限 | 计分 |
|---|---|---|---|
| **L0 冻结** | 正典规则、AAER 认定叙述、真实公司数字 | 无 | 是 |
| **L1 参数化模板** | 人写模板（显式区分 radicals/incidentals）+ 确定性代码填参算答案键 | 无（一个数字都不经过 LLM） | 是 |
| **L2 换壳** | 把已冻结的题改写成不同叙事语境（换行业/角色/措辞） | 有，但**数值集合、答案键、正典出处作为不可变载荷透传**，上屏前过确定性校验器（数字 exact match、accession 命中账本），不过就静默回退原文 | 是 |
| **L3 自由对话** | 追问、口头反事实、复述归类 | 完全释放 | **否**（不进档案、不进复训、不计校准分，UI 标注「教练的口头推演，非正典」） |

**「变体不等难」是必须写进实现的坑**：即使只改表层，同族变体的真实难度仍有方差——HLR 与校准分必须按变体各自记录，不能共用难度标签，否则会系统性污染 Brier Index。

**晋升通道**（把 owner 要的「持续生成」变成资产而非风险）：L2/L3 产生的候选题进候选池 → 规则引擎按 19 条写题缺陷检测（规则法命中率 91%，优于 GPT-4 的 79%）→ 数值确定性重算 → 出处存在性校验 → **仍需人工签字**才升级为 L1。产能按「**生成 100 → 上线 20–40**」排期，不要按「生成即上线」估算。

## 6. 对外展示方案（owner 第 2 条）

**三段式：Cloudflare Pages（前端）+ Cloudflare Workers（LLM 代理）+ named tunnel（只挂遥测），绑自有域名。**

- **前端 → Pages**：免费额度对单文件 HTML 富余四个数量级。**必须绑自有域名**（裸 `*.pages.dev` 国内表现尚可但非零风险）。排除 Vercel（`vercel.app` 国内 131 测 127 被墙）与 GitHub Pages（ToS 不允许商业托管 + 大量阻断）。
- **LLM 代理 → Workers，不要隧道回源**：这是**延迟决策不是成本决策**——隧道回源要多走一趟跨境 RTT，而首字延迟预算只有约 1 秒。代价是 Workers 无本地盘，Go+SQLite 不能整体搬；折中：Workers 只做代理+限流+数字守卫，遥测仍走 named tunnel 回自己的机器（遥测对延迟不敏感）。
- **隧道 → named tunnel，绝不用 quick tunnel**（`*.trycloudflare.com` 每次重启换 URL、官方明写仅供开发测试）。
- **演示三件套**：免登录直接玩；`?demo=1` 演示存档 + 一键重置（外部人要看的是「学到第 8 个节点长什么样」，不是空白档）；进度快照用 **URL fragment**（`#s=...`）不要用 query string（后者会进服务器日志、CDN 日志、微信转发记录）。
- **滥用防护不能省**：Turnstile（免费不限量）+ **自己在 Workers 里写限流**（CF 免费档的 Rate Limiting 只有 1 条规则、窗口锁死 10 秒，防不住刷爆 API 账单）+ Anthropic 控制台设月度支出上限。
- ⚠️ **微信不要当演示通道**：微信 Android X5 内核会周期性清 localStorage（社区多例报告 2–7 天），而我们的**全部学习进度就存在 localStorage 里**——这是形态级冲突，不是体验瑕疵。演示时引导「右上角…用浏览器打开」或直接投屏。

**成本**：单次「问教练」5 轮会话（5k 稳定前缀走缓存 + 每轮 80 入/400 出）在中档模型上约几美分；十人试用月成本个位数美元，百人规模几十美元。稳定前缀走 prompt cache（读 0.1×）是主要杠杆。

## 7. 需要 owner 裁决的清单

### A. 方向性裁决（决定要不要开工）

1. **接受「从 answer-based 升级到 step-based」这个重构方向**（而不是「换成聊天框」）？这是本提案的主张，也是唯一有 0.45 SD 量化支撑的方向。
2. **接受「锚题点亮」这条硬机制**？——对话免费、点亮收费，点亮只认闭卷迁移题。它会让学习者感觉「更难」，但它是唯一能证伪「对话到底有没有用」的机制。**不接受这条，我建议不要开工**：否则我们做的就是一个无法验证的第二个 GPT Base 组。
3. **v3 §2.6 的商业理由要不要重裁**？——「一个 C 端产品同时养活高频微题层和低频深度推理层无跑通先例」这条**至今没有被任何新证据推翻**。技术上我能给一条安全的路；**商业上这层能不能养活，只有你能裁**。

### B. 边界裁决

4. **动态场景能不能用真实公司**？建议**不能**——真实公司只走 L0/L1（模板+管线），LLM 换壳只用于叙事外壳。
5. **用户自由文本能不能进 prompt**？现契约写的是「永不进」，但 ① 先写这一步必然要进。建议改为**双面隔离**：分类面吃用户原文但只吐闭集 JSON；生成面完全不见用户原文。
6. **对话轮数上限**：现工程规范写死 2 轮，与「追问直到理解」互斥。建议放到 6 轮 + 到顶强制回落到一道检索题。
7. **两笔新增常态成本认不认**：每周 ≥60 条对话人工抽检（约 1–2 小时/周，永久）；误解库人工编写（14 节点 × 每题 3–7 条）。

### C. 顺序建议（若 A 通过）

- **第 0 步**（1 天，零契约变更）：把规则引擎状态注入教练 prompt + 系统主动触发。「教练没有感知」当天消失。
- **第 1 步**（1–2 天，零后端）：① 先写（纯前端，文本只存本地，不判分）。当天可上线，且是所有后续形态的原料。
- **第 2 步**：② 证据卡片收束 + 锚题机制。
- **第 3 步**（需后端）：③ LLM 闭集诊断 + 受约束追问。
- **第 4 步**：L1 参数化模板生成新变体。

### D. 我必须诚实说明的三处不确定

1. **没有任何一项 RCT 检验过「知识图谱 + 判断训练 + 事后受约束对话」这个组合形态**。上述分层是从相邻证据推演，不是复制某个已验证设计。
2. Kestin 那项 0.63–1.3 SD 是最亮的数字，但**无延迟保持测验、自研测验、作者自建干预、单课程两周、无独立复现**——只能支撑「高度脚本化的 LLM 辅导在讲授新概念时可能优于课堂讲授」，不能支撑「LLM 辅导优于结构化练习」。
3. 曾被广泛引用的「ChatGPT 提升学习 g=0.867」meta 分析**已于 2026-04-22 被撤稿**（撤稿前浏览 48.6 万次、引用 266 次）。更稳健的现役 meta 给出 g≈0.49，且最强调节变量是「AI 与结构并用」远优于「AI 替代结构」。**不要用 Bloom 两西格玛做产品叙事**——96 项随机辅导研究中零项复现，现实上限 0.3–0.8 SD。
