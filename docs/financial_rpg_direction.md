# 金融事件 RPG 改造简报

## 1. 产品定义

让已经在自己读财报的投资者进入真实金融事件，在当时有限的信息和角色约束下做关键决定。决定会改变后续能看到的材料、人物回应、调查路径和压力；故事结束后，再由画外音把玩家的选择与真实证据、真实结局和可迁移的判断方法连接起来。

这不是股票模拟器，也不是把课程换成卡片。核心体验是：

```text
进入事件 → 获得当时证据 → 选择角色立场 → 做关键决定
→ 看到由选择带来的后果 → 继续调查或承担压力
→ 对照真实历史 → 复盘自己的判断
```

## 2. 第一阶段垂直切片

先改 Sunbeam 1998 一幕，不同时重写全部五幕。

- 角色：投委会中唯一读完年报的人。
- 关键决策：继续求证、顺着转型叙事加仓、看到负现金流后直接清仓。
- 选择后果：三条路径分别进入求证压力、市场叙事压力、过早定性压力。
- 画外音：在选择之后即时回应，解释“你现在承担的是什么判断风险”，不提前揭晓真相。
- 真实揭示：仍然由原档引文和已核定事实完成，不能由 LLM 生成。

## 3. 内容模型改造

在 `case.json` 增加可选的 `rpg` 字段：

- `premise`：玩家在事件中的处境。
- `role`：玩家身份、目标、约束。
- `narrator`：画外音身份、语气、边界。
- `decision`：关键决定的 id、压力、选择后的路径。

在 `beats` 中增加 `consequence` 拍：

- 每个 `paths[option_id]` 提供路径标题、后果、下一步提示和本地 fallback 画外音。
- 不携带新的未经核定事实。
- 真实结局仍只能出现在 `reveal` 之后。

## 4. LLM 边界

LLM 负责：

- 沿用户选择改写画外音；
- 回应用户对当前处境的语言反馈；
- 在给定材料内解释选择带来的判断风险。

LLM 不负责：

- 判定用户选择对错；
- 创造真实事件、数字、引文或结局；
- 代替历史人物说出没有出处的话；
- 给买卖建议或预测价格。

所有生成文本都必须有本地 fallback，并经过长度、数字、越界词和 hindsight 检查。

## 5. 成功标准

第一阶段不看内容数量，先看一条链路是否成立：

1. 用户能说清自己扮演的角色和当前压力。
2. 三种选择会显示不同后果，而不是只显示不同点评。
3. 用户会主动想重试另一条路径。
4. 画外音增强沉浸感，但没有泄露真实结局。
5. 构建门禁仍通过，原档事实校验和自动定版哈希机制不被绕过。

## 6. 非目标

- 第一阶段不做开放世界、多角色并行关系网。
- 不做股价涨跌模拟。
- 不把历史结局改写成“玩家真的改变了历史”；玩家改变的是信息路径、决策压力和复盘结果。
- 不提前做章节懒加载或复杂后端会话系统。
