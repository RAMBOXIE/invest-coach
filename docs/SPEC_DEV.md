# 开发规范 · v1

> **为什么有这份文档**：owner 2026-08-25 的批评——「现在的看结果是比较随机发散的，比如手机里的可读体验就是不好的，是不是每次开发前都在开发的整体要求下，是否合理的创建了文件夹」。
> **本规范的元规则**：**每一条都必须是可判定的数值或可执行的检查**。出现「适当」「合理」「尽量」的条款视为无效条款。凡是能被 `tools/` 里的脚本挡下来的，就不写进「注意事项」。
> **配套**：`docs/STRUCTURE.md`（目录登记表）｜`docs/CHECKLISTS/preflight.md`（开工前八问）｜`design/tokens.json`（设计令牌单一真源）。
> **与既有文档的关系**：`docs/工程化规范.md` 降级为「管线与后端规范」（它覆盖取数/后端/门禁/Git，零覆盖 UI 排版与目录纪律——正是本次批评落点）。

## 1. 目录结构（唯一合法形态）

```
invest-coach/
├── design/
│   └── tokens.json              ★ 设计令牌单一真源；CSS 变量由构建期生成，不手写
├── content/
│   ├── ch1/{site.json, facts.json}
│   ├── stories/<case_id>/{case.json, facts.json}
│   └── current/                 时事管线产物（staging，未签字）
├── evidence/                    原档存档 + sha256 锚定（.gitattributes 标 -text）
├── src/
│   ├── shell.html               骨架，含 <!--#part:xxx--> 占位
│   └── parts/                   ★ 源码分片（css/*.css, js/*.js），构建期拼装
├── tools/
│   ├── build.py validate.py fetch_current.py
│   ├── check_a11y.py check_budget.py     ★ 视觉与性能门禁
│   └── oneoff/                  ★ 一次性脚本的唯一归宿，文件名 YYYYMMDD-用途.py
├── docs/
│   ├── SPEC_DEV.md STRUCTURE.md
│   ├── CHECKLISTS/preflight.md
│   └── adr/NNNN-标题.md         架构决策记录
└── dist/                        构建产物（gitignore）
```

**三条目录纪律（违反即打回）**
1. **新建任何目录前，先在 `docs/STRUCTURE.md` 登记一行**（路径 / 用途 / 谁写 / 谁读 / 生命周期）。未登记的目录，`validate.py` 报 ERROR。
2. **仓库根目录不新增任何文件夹**。所有新东西必须落进上表已有的七个一级目录之一。
3. **一次性脚本不许留在 scratchpad**。改内容的脚本一律进 `tools/oneoff/YYYYMMDD-用途.py` 并提交——因为它是内容变更的唯一可追溯记录。

> 本条直接回应「是否合理地创建了文件夹」。此前把改内容的 Python 脚本放在临时目录，等于内容变更没有版本记录，这是这次批评里最实的一条。

## 2. 设计令牌（`design/tokens.json`，单一真源）

CSS 变量**由构建期从 tokens.json 生成**，源码里不许出现字面色值与字面字号。分三层：

- **primitive**：`color.ink.900`、`size.16` —— 原始值，不带语义
- **semantic**：`text.body`、`surface.stage`、`state.flag` —— 语义槽位，UI 只许用这一层
- **component**：`btn.primary.bg` —— 组件级，从 semantic 派生

命名：`层.类别.角色.状态`，全小写点分。禁止在组件里直接引用 primitive。

## 3. 移动可读性硬指标（全部可机器核对）

| 项 | 硬指标 | 依据 |
|---|---|---|
| 叙事正文字号 | `clamp(17px, 4.6vw, 19px)` | 中文小字号在暗底上劣化最严重；17px 是 CJK 正文下限 |
| 叙事正文行高 | **1.85** | CJK 需高于西文的 1.5 |
| UI 文本 | **≥15px** | — |
| 辅助/元信息 | **≥13px** | 此前用 10.5px / 11.5px，全部违规 |
| 每行字数（measure） | **中文 20–30 字**；容器 `max-width: 34em` | 超过 30 字/行时回视率上升 |
| 段间距 | ≥ 1.5 × 行高 | — |
| 正文对比度 | **≥7:1（AAA）** | 当前 `.foot` 为 3.86:1，**连 AA 4.5:1 都不达标** |
| 辅助文本对比度 | ≥4.5:1 | WCAG 1.4.3 |
| 图形/边框对比度 | ≥3:1 | WCAG 1.4.11 |
| 触控目标 | **≥44px，推荐 48px**，间距 ≥8px | iOS HIG 44pt / Material 48dp |
| 文本间距抗覆盖 | 注入 `letter-spacing:.12em; word-spacing:.16em; line-height:1.5; margin-bottom:2em` 后**无内容裁切** | WCAG 1.4.12 |
| 全屏幕卡高度 | `min-height: 100svh`，**禁止写死高度** | 写死高度过不了 1.4.12 |
| 字体 | 正文永远系统无衬线（0 字节）；衬线只用于幕标题/引语/年份，**精确子集 ≤28KB** | 中文正文衬线子集要 70–140KB，装不下 |

**深浅双极性分层（不做全站深色）**：幕层（场景/黑场/数据大字/教练字幕）用深色；**读区层（知识点/长文/原档摘录）用亮场**。正极性在小字号下优势最大，而中文正文正是小字号最坏情况。主题切换当作「进入/退出回忆」的转场语义，不做成设置项。

## 4. 性能预算

| 项 | 阈值 |
|---|---|
| `dist/index.html` | ≤300KB |
| LCP | <2.5s |
| INP | <200ms |
| CLS | <0.1 |
| 滚动帧率（中端 Android + 微信 WebView） | ≥50fps，无整页重绘 |
| 动效时长 | ≤200ms（微交互）/ ≤400ms（转场） |

**禁用清单**（性能或合规陷阱，需 ADR 才能豁免）：`background-attachment:fixed`（iOS 不支持、Android 每帧整页重绘）｜全屏位图/视频｜自定义中文正文字体｜滚动劫持｜横向滑动承载主流程｜打字机逐字动画｜视差。

**史诗感实现手段白名单**（只许用这些）：超大字号阶梯（标题 40–64px）、大留白、内联 SVG 线条与时间轴、CSS 渐变与噪点、≤200ms 微动效、竖向滚动叙事、**真实原档的等宽字体 + 行号 + 高亮带渲染**。

> 最后一条同时解决两个问题：它是最强的「档案感」画面，且零版权、零体积、零 LLM 生成——**我们展示文件，不展示人**。

## 5. 源码组织

- `src/shell.html` 只保留骨架与 `<!--#part:name-->` 占位；样式与逻辑分片进 `src/parts/`。
- 构建期由 `build.py` 拼装成单文件。**「单文件交付」是产品特性，「单文件源码」不是**——此前 900 行巨型 HTML 被多轮脚本打补丁，是发散的直接原因。
- CSS 用 `@layer tokens, base, layout, component, utility` 组织，禁止无层级裸写。
- 注释密度：只在算法处（调度、校准、判分、渲染节拍）写「为什么」，不写「是什么」。

## 6. 无障碍基线（发布必过）

语义化标签与 landmark ｜ 键盘可达且焦点可见 ｜ `prefers-reduced-motion` 分支**必须声明**（关闭动效后**分阶段揭示的阶段与注释全部保留**，只是没有补间）｜ 表单与按钮有可及名称 ｜ 颜色不是唯一信息载体（红旗必须同时有文字标记）。

## 7. 开工前八问（`docs/CHECKLISTS/preflight.md`，每次动手前逐条回答）

1. 这次改动属于哪一层（内容 / 令牌 / 组件 / 管线 / 文档）？
2. **需要新建目录吗？已在 STRUCTURE.md 登记了吗？**
3. **要写的每个数字，都有 fact_id 吗？** 没有就先走取数管线。
4. 会改到已签字内容吗？改了就要重新签字（hash 绑定会自动失效）。
5. 手机 390×844 的屏级草图画了吗？（先画屏，再写码）
6. 新增的文本达到 §3 的字号/对比度/行长指标了吗？
7. 有静态兜底吗？（后端不可达 / LLM 失败时，体验降级但不缺角）
8. 这次改动如何被机器挡住回归？（新增哪条 validate 规则）

## 9. 机器门禁分工

| 工具 | 管什么 |
|---|---|
| `validate.py` | 内容真值与结构（R1–R25 已有）+ 目录登记 + 数字必须绑 fact_id |
| `check_a11y.py` | 字号下限、对比度对照表、触控尺寸、1.4.12 抗覆盖、reduced-motion 分支存在性 |
| `check_budget.py` | 体积预算、禁用清单扫描、每幕字数上限 |
| `build.py` | 令牌生成 CSS 变量、源码分片拼装、facts 注入；**任一门禁 FAIL 即拒绝构建** |
