## 3. 边表与理由（审方向用）

### hard（16 条，解锁门）

| from → to | 为什么是前置 |
|---|---|
| 三张表 → 先记账后收钱 | 先知道有哪几张表，才谈得上「利润表和现金流量表为什么不同」 |
| 三张表 → 经营现金流 | 现金流量表的位置与三段分类 |
| 三张表 → 第一案 | 第一案只要求「知道数字是什么」+「会算增速」，门槛刻意压到最低 |
| 增速 → 第一案 | 同上 |
| 先记账后收钱 → 应收账款 | 应收 = 权责发生制的直接产物（记了收入没收到钱的存放处） |
| 先记账后收钱 → 红旗二 | 理解背离机制的前提：利润与现金天然有时间差 |
| 应收账款 → 红旗一 | 科目本身是信号的载体 |
| 第一案 → 红旗一 | **案例先行的结构化落点**：先直觉判断过，再学正式工具（Bierstaker，§3.3.5） |
| 第一案 → 红旗≠实锤 | 你刚做过一次判断，现在告诉你底率——时机最佳 |
| 经营现金流 → 红旗二 | 科目载体 |
| 红旗一 → 回款要几天 | DSO 是红旗一的精细化，不先懂增速对比无从谈等价性 |
| 红旗一 → 先替它辩护 | 无辜解释训练挂在第一面红旗后，立刻可用 |
| 红旗一 → 让现金作证 | 印证流程的起点是「看见」 |
| 红旗二 → 让现金作证 | 印证流程的工具是红旗二 |
| 让现金作证 → 终局对决 | 终局要求完整的看见→求证链 |
| 终局对决 → 你的清单 | 清单必须出现在案例之后（§3.3.5 不可协商） |

### soft（2 条）

| from → to | 语义 |
|---|---|
| 应收账款 → 红旗二 | 应收是 NI−OCF 缺口最常见的去向——学过更好，不强制 |
| 回款要几天 → 终局对决 | 终局材料含 DSO 行，会算更从容，不会也能解 |

### cross（2 条，元能力，§3.1）

| from → to | 语义 |
|---|---|
| 红旗≠实锤 → 让现金作证 | **印证的动机来自基率**：正因为单红旗多半无辜，才必须求证 |
| 先替它辩护 → 终局对决 | 整案判别的第一步就是替双方找无辜解释 |

Validator 自查（对照 agent-graph-learning 规则）：无环 ✓；hard 边层深单调 ✓；无传递冗余（hard 闭包逐条查过，如 `growth-rate→rf1` 已因 `growth-rate→case-first-look→rf1` 而省去）✓；根节点 = 三张表、增速两个 ✓；canon.source 全部指向 sources 数组 ✓。`screens` 全空是有意的——那是第 2 步。

## 4. 混淆对清单（8 对，§3.6 一等公民）

## 6. 待裁决问题 → 已全部裁决 ✅（2026-08-22，8/8 按倾向通过，原文留档）

1. **首案→终局的叙事弧**：第一案匿名用 Sunbeam 真数字，终局实名揭示「你第一课就见过它」。代价是终局对 Sunbeam 的「新鲜感」减半——判别难度主要落在对照公司身上。**我的倾向：保留**（故事闭环+复用一套已核数字，且终局考的是判别不是识旧）。备选：首案改用虚构面板或另一实名案。
2. **`dso` 节点去留**：Schilit 正典工具、红旗一的等价精细化；但第一章以 L1 面板为主，DSO 是唯一要做除法的节点。砍掉则 14→13，图更轻。**我的倾向：保留**，soft 通向终局（材料可用可不用）。
3. **「判断+一句话理由」的第一章形态**：§2.6 规则判分 ⇒ 我按「判断规则判分 + 理由做成多选（你的主要依据是？）+ 自由文本框选填仅存档」设计。自由文本第一章完全不判分，只进错题档案供复盘。请确认。
4. **`accrual-basis` 合并了收入确认**：权责发生制与收入确认合为一节点（红旗一的归因链只需要「先记账后收钱」这一个概念）。拆开会多一个节点但每个更薄。**我的倾向：合并**。
5. **元能力第二席给了证伪（ACH）而非「相关 vs 因果」**：理由是混淆对训练的直接理论支撑就是竞争假设 + Heuer 是公有领域正典（与 AAER 同档）。相关 vs 因果留给第二章（现金流章更需要它）。
6. **`checklist-after` 作为节点**（而非产品功能页）：§3.3.5 的「清单后置」需要被显式教一次，否则用户自己会把清单当初判工具。**我的倾向：保留节点**。
7. **`ageStart` 重用为层深**：validator 的单调性检查借此继续有效，UI 显示「第 N 层」。若将来模板硬编码「岁」字样，POC 阶段改模板文案。
8. **元能力节点带一条 hard 入边**（`case-first-look→base-rate`、`rf1→falsification`）：§3.1 只说 cross 边连元能力节点，未禁止 hard 入边——不加则它们成为开局即解锁的孤根，时机全错。我按「hard 定解锁时机 + cross 表达跨域贡献」处理。请确认这不违反你对 §3.1 的本意。

# 附录 A · 审图 v2（2026-09-02）—— 冻结版 `ch1-graph-v2`

> v1 冻结于 2026-08-22。本次改动动了冻结范围（边的类型、节点集合、混淆对语义），
> 按 v1 的纪律必须重新留档。**改动很小：两条边改类型、删一条传递冗余边、加一个节点。**

## A1. 为什么要动 —— 两个元能力节点是可以完全绕过的

`stateOf()` 只认 `hard` 边。而 `base-rate`（异常信号不等于结论）与
`falsification`（先替它辩护）当时**只有 cross 出边**，于是它们不是任何节点的前置：

    three-statements → accrual-basis → receivables → rf1 → corroborate → case-final → checklist-after

这条主线一个元能力节点都不碰。产品把「异常信号只是核查的理由」和
「先替它辩护」当作区别于一张核对清单的地方，结构上却把它们做成了选修读物。

**这不是疏忽，是 v1 §6 第 8 条的裁决被实现打了折。** 原文写的是
「hard 定解锁时机 + cross 表达跨域贡献」——前半句实现了（两个节点都有 hard 入边，
时机正确），后半句没有：cross 在引擎里不产生任何约束，「贡献」等于没有表达。

## A2. 改了什么

| # | 改动 | 理由 |
|---|---|---|
| 1 | `base-rate --cross--> corroborate` ⇒ **`base-rate --hard--> rf1`** | rf1 是第一个被命名的异常信号。把「信号不等于结论」放在第一个信号**之前**是免疫接种：让学习者在见到第一个信号之前就没有机会养成一见信号就下结论的习惯。base-rate 在第 3 层、rf1 在第 4 层，层序成立 |
| 2 | `falsification --cross--> case-final` ⇒ **改为 hard** | case-final 是综合判断，要在两家公司之间定性。没学过「先列出正常解释再逐个排除」就去做这件事，正是这个产品想防的那个错误。同一条边，只是让它真的生效 |
| 3 | 删 `case-first-look --hard--> rf1` | 改动 1 之后它成了传递冗余（case-first-look → base-rate → rf1），validate 当场报错。删掉后路径读起来更清楚：先看一遍完整的事 → 学会信号不等于结论 → 再学第一个信号 |
| 4 | 新增节点 `find-filings`「去哪找年报」（第 1 层，根）+ **`hard --> rf1`** | 全章 24 次要求「去查附注」「看会计政策」，却没有一屏教这些东西在哪。收官口袋卡第 ⑥ 条「读附注」是全卡唯一一个学习者做不到的动作。放第 1 层是因为它没有概念前置；gate 在 rf1 是因为那里才第一次真的需要它 |

调度实测（按 hard 边 + ageStart 求最短路径）：

    1 三张表的分工 → 2 增速怎么算 → 3 去哪找年报 → 4 先记账后收钱 → 5 第一个案例
    → 6 应收账款 → 7 经营现金流 → 8 异常信号不等于结论 → 9 应收增速高于收入增速
    → 10 利润没变现金 → 11 回款要几天 → 12 用现金流核查 → 13 先替它辩护
    → 14 两家公司对照 → 15 你的清单

## A3. 代价（不藏）

**图更串行了。** v1 的 cross 边表达的是「有贡献但不阻塞」，那个想法本身有价值——
它允许一个只想学信号识别的人先走过去。改成 hard 之后这条路没了：想学 rf1，
就必须先过 base-rate。

我认为这个代价值得付，因为「可以跳过」在这里等于「多数人会跳过」，
而跳过的恰好是这个产品唯一区别于一张清单的东西。但这是一个取舍，不是一个纯粹的修复。

**如果将来要恢复灵活性**，正确的做法不是把边改回 cross，而是给引擎加一个
「soft-gate」概念（可以跳过但会明确提示欠着什么），而不是让约束静默消失。

## A4. 随之而来的结构补齐

`base-rate` / `falsification` / `checklist-after` 以及 5 个基础概念节点原本
**没有 x_pairs、没有 x_anchors**——也就是说它们无法用闭卷题证明学会了，
「通过」全靠答完屏内题。既然元能力现在是硬前置，它们尤其需要迁移证明。

本轮给全部 8 个此前无闭卷题的节点补 1 个混淆对 + 2 道闭卷题（混淆对语义在冻结范围内，
逐对列在 A5）。新增节点 `find-filings` 同样配齐。

## A5. 新增混淆对（冻结范围，逐对留档）

| 节点 | 表象（look） | a 面 | b 面 | 区分线索（key） |
|---|---|---|---|---|
| three-statements | 两个数字都叫「收入」 | 利润表的营业收入（一段时间累计） | 资产负债表的应收账款（某一天的余额） | 问这个数字是某一天的，还是一段时间累计的 |
| growth-rate | 两家都说自己「涨得多」 | 绝对增量大但增速低（基数大） | 绝对增量小但增速高（基数小） | 看分母：涨幅比的是相对去年，不是多出来多少钱 |
| find-filings | 两个问题都要「查年报」 | 想知道赚了多少 → 报表本体（Item 8 内） | 想知道收入怎么确认 → 附注的重要会计政策（同在 Item 8 内） | 数字本身看报表，数字怎么来的看附注 |
| accrual-basis | 货和钱没同时发生 | 已交付未收钱 → 确认收入，挂应收账款 | 已收钱未交付 → 不确认收入，挂预收/合同负债 | 看义务履行了没有，不看钱到了没有 |
| receivables | 名字里都有「收/付」 | 应收账款：别人欠我 | 应付账款：我欠别人 | 钱的方向：将来会流进来还是流出去 |
| ocf | 都是「收到了钱」 | 卖货收到的钱 → 经营活动 | 卖厂房收到的钱 → 投资活动 | 这笔钱是靠主营业务赚的，还是靠处置家当换的 |
| base-rate | 都是「10%」 | 先验：100 家公司里约 10 家有问题 | 后验：见到信号的公司里有多少有问题 | 后者还需要知道信号在两类公司里各自的出现率，前者推不出后者 |
| falsification | 都叫「正常解释」 | 已被一条具体证据顶掉的解释 | 只是听起来不太可能、但没有证据顶掉的解释 | 有没有一条能指出来的证据把它排除掉 |
| checklist-after | 都在用同一张卡 | 先自由判断，再用卡查漏 | 照着卡逐项往下勾出结论 | 你是先有了判断再对表，还是让表替你思考 |

## A6. 未做的取舍

**5 个基础概念节点（三张表 / 增速 / 权责发生制 / 应收 / 经营现金流）也补了闭卷题，
但保持两步节奏。** 曾考虑不给它们补——理由是「定义性节点不需要迁移测试」，
且 P0-5 定了前三次会话 ≤5 分钟。实测一道闭卷题约 40 秒，基础节点从约 3 分钟到约 3.7 分钟，
仍在约束内；而「每道题都是闭卷的」是对外说的话，留 5 个例外会让这句话不成立。
