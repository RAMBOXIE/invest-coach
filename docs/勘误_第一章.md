## 门禁升级（同轮实施，R14–R22）

红队结论：**旧门禁 20 个攻击场景 20 个全部溜过**（13 个经变异实测），它是形状校验器不是真值校验器。本轮新增：

| 规则 | 内容 |
|---|---|
| R14 类型闸 | canon.formal 含「SEC 认定/指控/AAER」⇒ source.type 必须是官方认定；含「ASC/IFRS/IAS/五步模型」⇒ 必须是会计准则 |
| R15 时代闸 | 从 source 的 name/note 抽年份，概念不得早于出处年份（现金流量表 ≥1987、ASC 606 ≥2014、DSRI ≥1999） |
| R16 精确引用 | `canon.x_cite`（章节/页/条款号）缺失即 WARN；canon 层 `x_` 白名单 |
| R17 深层题必备 | 带 `x_level` 的节点，其 main/pretest/review 题必须 `confidence=true` + 恰 3 条 hints + 含 1 个 na 选项（**规范里早已写成 ERROR，但代码从未实现**） |
| R18 覆盖不可静默关闭 | `x_covers` 空集即 ERROR（旧实现删空字段即绕过） |
| R19 枚举与递归白名单 | 白名单递归到 quiz 层；`x_level∈{L1,L2}`、`x_kind∈{main,pretest,decision,review}`；题内出现 llm/judge 字样即 ERROR（§2.6 工程锁）；教练 `canon_sources` 必须命中 sources[]、`when` 枚举、台词 ≤40 字、**人格字段不得出现出处作者姓氏**（替代已裁撤的禁词扫描） |
| R20 答案键约束 | main/pretest/review 恰 1 个 ok:true（防「多标一个正确」的一行 diff 投毒）；复训题 `quiz.x_pair == pair_id`；side 必须是 a/b；pair_id 必须存在 |
| R21 待办标记扫描 | 内容中出现「待核/待补/待定稿/TODO/推荐沿用/候选方向」即 ERROR |
| R22 na 分布锚 | 「无法判断」为正确答案的占比：<10% 或 >45% ERROR，非 20–30% WARN |

**变异复测结果：10 个攻击 9 挡住**。唯一仍能溜过的是「canon 挂 sources 里存在但不相干的文献」——语义相关性机器判不了（内容曲解检测最强系统 precision 仅 40.8%），只能靠 R16 的 `x_cite` 把它变成人工两秒可查（填不出章节号的弱挂靠自然暴露），最终仍需 G1 人工门。
