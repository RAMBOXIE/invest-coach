# LLM 用途登记簿

> **宪章（owner 裁决，2026-08-22）**：「最重要的是整体考虑项目的健壮性，使得项目最终的教学是可靠的、可溯源的。数据也应当使用正确的方法来进行使用，**LLM 仅作推理和细致的教练引导、原因解释**。通过我们的软件让散户投资者有更好的投资知识和能力。」
>
> **登记制**：任何新的 LLM 用途必须先在本表登记（比照 SCHEMA.md 的 x_ 字段登记制），未登记即违规。四类边界的完整依据见 `知识可靠性与LLM边界_v1.md` §4。

## 铁律（不随用途变化）

1. **事实不出自 LLM**：真实公司数字、准则条文、官方认定只能来自原档取数管线（EDGAR accession+行号 → facts.json → 人工核定），LLM 只解释已核定的材料。
2. **判分永不经 LLM**（v3 §2.6）：判分=前端规则引擎；运行时 LLM 不改判、不给分、不暗示判分有误（validate R19 有工程锁：内容中出现 llm/judge 字段即 ERROR）。
3. **LLM 起草的用户可见文本必须人工逐条签字**（x_prov.reviewed_by + 内容 hash 绑定，改动即审核过期；`--release` 未签字即阻断发布）。
4. **自审无效**：审核者不得是起草同批内容的模型/会话；机器溯源只做筛子（推进人工队列），永不签核通过。

## 明令禁止（A 类，永久）

生成/改写 canon 定义与出处 ｜ 生成真实公司数字或派生比率 ｜ 判分/改判/评分/评级 ｜ 前瞻信号、收益承诺、个股建议、真实主体在材料时点之后的状态 ｜ 输出材料中不存在的阈值/公式/筛选参数 ｜ 运行时检索（RAG，见可靠性文档 §1.1 裁决）

## 数据的正确用法（owner 原则的落点）

- **数字只有一条进入路径**：EDGAR/AAER 原档（evidence/ 存档 + sha256）→ 人工核定（数据核定文档，行号级）→ facts.json 机器账本 → validate R12 强制正文命中账本。LLM 在这条链上没有位置。
- **构造题豁免出处、不豁免自洽**（R13）；真实公司语境的每个数字 token 必须能指回账本条目。
- **遥测数据**：匿名、带 content_version/quiz_id/side/屏级事件（可归因），统计只产出人工复核队列（G4），永不自动改内容；「问教练」输入按敏感数据管理（保留期+打码+提示），不冒充「匿名使用数据」。
