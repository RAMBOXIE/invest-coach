# ADR-0001：判分与 LLM 的关系

- 日期：2026-08-26
- 状态：已裁决 · 2026-09-02 补充第 2 节（教练读开放文本）

## 两条规则，不要混为一谈

| | 规则 | 状态 |
|---|---|---|
| ① | **事实不出自 LLM** —— 真实公司数字、准则条文、官方认定只能来自原档取数管线（EDGAR accession + 行号 → `facts.json` → 人工核定）。LLM 只解释已核定的材料 | **铁律** |
| ② | **判分不经 LLM** —— 对错由前端确定性规则给 | **推迟，不是禁止** |

① 是产品的立身之本（可靠、可溯源）。② 是工程选择。

## ② 为什么现在仍然这么做

不是禁令，是三条现实收益：

- **离线可用** —— 没有后端、断网、超时，判分照常。这是单文件交付形态的一部分
- **零延迟** —— 答完立刻出反馈，不等一次网络往返
- **可复现** —— 同一份答案永远得到同一个判分。做不到这点，勘误台账就无从谈起

质问台的语义路由不受影响，它本来就不是判分：LLM 的全部输出是一个证词 id，
文本一律取自 `case.json`（见 LLM_USE_REGISTRY #8）。

## 要引入 LLM 判分，先满足这些

排在最前的是**它能解决而规则引擎解决不了的那个问题**：
现在只能判选择题，判不了「用你自己的话说出你的推理链」。那才是 step-based 教学的终点。

1. **只判开放文本，不动选择题的判分。** 规则引擎那条路不许被替换
2. **判分理由必须可回放** —— 存下 prompt、rubric、模型输出，用户能看到「为什么这么判」。
   做不到可回放就不上
3. **先做成不计分的第二意见**（「教练还看到了这些」）。判分影响 Brier 校准分与锚题点亮，
   跑一段时间再谈计分
4. **离线降级路径** —— 没有后端时开放题怎么办，要有明确答案
5. `validate.py` **R19 的工程锁**（内容里出现 `llm` / `judge` 字段即 ERROR）**暂时保留**。
   它挡的是「悄悄把判分接进 LLM」，不是挡这条设计路线。真要做时连同这条锁一起改，
   并在本 ADR 补一节说明改成了什么

## 引用纪律

外部收敛文档写全路径 `research/投资教练_收敛_v3.md §N`，仓库内文档写文件名 + 节号。
**其它文档只许引用本 ADR，不许各自复述结论。**

## 2026-09-02 补充：教练读你写的那段话

本 ADR 原文写着「排在最前的是它能解决而规则引擎解决不了的那个问题：
现在只能判选择题，判不了『用你自己的话说出你的推理链』」。这一节记录那件事做了什么。

**触发**：owner 指向 r/ClaudeAI 的一个手写笔记应用（3881 赞），
说「这样类似的快速交互的体验我认为才有 AI 教练的及时反馈的感觉」。
那个应用的机制是：你写，Claude 在同一页写回来。
关键不在手写，在**交互单元是学习者自己产出的东西**，而不是从三个选项里挑一个。

### 做了什么

深层节点第 2 步「先写」原本是写完存本地、不做任何回应。现在：
学习者写完，**教练就地写回一段话，不翻页**。

`POST /api/v1/review-note`：拿到这一关的已核定材料 + 学习者写的文字，
返回两三句回应。

### 五个前置条件逐条对照

| # | 条件 | 落法 |
|---|---|---|
| 1 | 只判开放文本，不动选择题的判分 | 这条路径**不判分**。选择题的判分链一行没动，Brier 校准分与节点通过条件都不受影响 |
| 2 | 判分理由必须可回放 | `notes` 表存下完整 trace：system 提示词、学习者原文、模型原始输出、出口检查结论 |
| 3 | 先做成不计分的第二意见 | 就是当前形态。教练说的话不进成绩、不进错题档案、不改任何计数器 |
| 4 | 离线降级路径 | 没开开关 / 没有后端 / 请求失败 / 出口检查丢弃，四种情况都回落**本地反馈**：把学习者写的和这一关的证据卡做词面比对，说清他提了哪几条、漏了哪几条。不联网、不上传 |
| 5 | R19 的工程锁一起改 | **没有改，也不需要改。** 那把锁挡的是内容里出现 `llm`/`judge` 字段（「悄悄把判分接进 LLM」）。这条路径不往内容里加任何字段，判分也仍由前端规则完成，锁原样保留 |

### 「事实不出自 LLM」这条铁律怎么守

**不靠提示词。** 提示词里写了「不许引入任何新的事实、数字、公司名、年份」，
但那只是第一道。真正的保证是**服务端出口检查**（`check_note`）：

模型输出里出现的每一个数字，都必须在我们喂给它的已核定材料里出现过；
出现越界措辞（建议买入/卖出、目标价、推荐）也一律丢弃。
不合格就整条扔掉，前端回落本地反馈。

**宁可没有教练回应，也不能让一个编出来的数字挂上「教练」两个字。**

材料由前端组装后随请求发出（节点的 canon.formal + evidence + 证据卡 + 排除项），
服务端保持无状态——模型能引用的东西**只有我们给它的这些**。

### 隐私承诺改了

「先写」那一屏原本印着「这段文字只存在这台设备上：不上传、不进记忆、不进 AI 的输入」。
教练要读它，这句话就不再成立。

处理：加一个**默认关闭**的开关，两种状态下的文案都说真话——
关着时仍是原来那句承诺；打开时明写「这段文字会发到我们的服务器交给 AI 读一遍」。
不静默改语义，也不把开关默认打开。

### 还没验的

**真实 LLM 路径没有端到端跑过**，因为本机没有 `CLAUDE_API_KEY`。
已验的是：出口检查的单元行为（编造数字被丢弃、越界措辞被丢弃、
空与超长被丢弃）、无 key 时后端正确返回 fallback、前端四种降级情形都回落本地反馈。
接上 key 之后要补一次真实往返，重点看出口检查在真实输出上的误杀率。
