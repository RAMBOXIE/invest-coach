# ADR-0001：判分不经 LLM

- 日期：2026-08-26（追认，规则本身更早）
- 状态：**现行，但出处存疑——待 owner 复裁**

## 规则

判分由页面内置的**确定性规则**完成。运行时 LLM 不判分、不改判、不暗示判分有误。
LLM 只做三件事：推理与教练式引导、原因解释、以及「用户想戳哪条」的**语义路由**
（输出只是一个证词 id，答案文本一律取自 `case.json`）。

这条写在 CLAUDE.md 的「两条不可协商的铁律」里，也写在 LLM_USE_REGISTRY.md 顶部。

## 出处存疑

四份派生文档都把它记在「v3 §2.6」名下，声称上游裁决过「LLM 判卷是永久禁区」。
`_superseded/形态重构提案_v1.md` §3 查证后发现**不是**：

> v3 §2.6 的逐字原文是：「深度判卷层（完整决策陈述 + LLM 全 rubric 判卷）**推迟**」，
> 理由是**商业先例**……——**不是**「LLM 判卷不可靠」。
> 是我在四份派生文档里把「推迟」硬化成了「永久禁区」并记在 §2.6 名下。

也就是说：**规则可能是对的，但它现在挂着一个错误的出处**，而且是被自己人硬化出来的。
这恰好是本仓库反复强调的那类错误（机器门禁只查形状不查真值）在文档层的同构版本。

## 待办

请 owner 就「判分是否永久禁止经过 LLM」补一次明确裁决，两种结果都可接受：

- **确认永久禁区** → 本 ADR 状态改为「已裁决」，删掉「出处存疑」一节，
  CLAUDE.md 与 LLM_USE_REGISTRY.md 改为引用本 ADR。
- **恢复为「推迟」** → 本 ADR 记录推迟的条件（商业先例 / 法律评估），
  CLAUDE.md 的措辞从「铁律」降级为「当前阶段的约束」。

在复裁之前，**代码按现状执行**（判分不经 LLM），不改行为。

## 引用纪律

外部收敛文档一律写全路径 `research/投资教练_收敛_v3.md §2.6`，
仓库内文档写文件名 + 节号。仓库里曾同时存在两份「v3」，`§2.6` 在仓库内会解析到错的那份。
