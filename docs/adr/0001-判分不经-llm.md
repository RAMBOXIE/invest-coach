# ADR-0001：判分与 LLM 的关系

- 日期：2026-08-26（owner 复裁）
- 状态：**已裁决 —— 不是永久禁区**
- 取代：此前四份派生文档里「判分永不经 LLM（v3 §2.6）」的表述

## 背景：一条被自己人硬化出来的铁律

四份派生文档都把「LLM 判卷是永久禁区」记在上游 `research/投资教练_收敛_v3.md §2.6`
名下。查证后发现**上游原文不是这么说的**：

> v3 §2.6 的逐字原文是：「深度判卷层（完整决策陈述 + LLM 全 rubric 判卷）**推迟**」，
> 理由是**商业先例**……——**不是**「LLM 判卷不可靠」。
> 是我在四份派生文档里把「推迟」硬化成了「永久禁区」并记在 §2.6 名下。

也就是说：规则被执行了很久，但它挂着一个错误的出处，而且是被自己人加码出来的。
这正是本仓库反复强调的「**只查形状不查真值**」在文档层的同构版本。

## 裁决

owner 2026-08-26：**不禁 LLM。**

「判分永不经 LLM」**不再是不可协商的铁律**，恢复为上游本来的意思：
LLM 判卷是**推迟**的（商业先例 + 成本 + 体验成熟度），不是被否决的。

## 但必须分清两条规则 —— 它们过去被混为一谈

这是本次裁决最要紧的一点。原来的「铁律」实际上捆了两件不同的事：

| | 规则 | 状态 |
|---|---|---|
| **①** | **事实不出自 LLM** —— 真实公司数字、准则条文、官方认定只能来自原档取数管线（EDGAR accession + 行号 → `facts.json` → 人工核定）。LLM 只解释已核定的材料 | **仍是铁律，不受本次裁决影响** |
| **②** | **判分不经 LLM** —— 对错由前端确定性规则给 | **解除永久禁令，改为推迟；引入需满足下面的条件** |

**①才是这个产品的立身之本**（可靠、可溯源），②只是当时的一个工程选择。
把两者捆在一起，导致②被误当成不可动的，而讨论①的空间反而被挤没了。

## 现在怎么执行

**代码不变**：判分仍由前端确定性规则完成。理由不是禁令，是这三条现实收益：

- **离线可用**：没有后端、断网、超时，判分照常——这是单文件交付形态的一部分
- **零延迟**：答完立刻出反馈，不等一次网络往返
- **可复现**：同一份答案永远得到同一个判分；LLM 判分做不到，也就没法做勘误台账

**质问台的语义路由不受影响**，它本来就不是判分：LLM 的全部输出是一个证词 id，
文本一律取自 `case.json`（见 LLM_USE_REGISTRY #8）。

## 要引入 LLM 判分，先满足这些

排在最前的是**它能解决而规则引擎解决不了的那个问题**：
现在只能判选择题，判不了「用你自己的话说出你的推理链」。那才是 step-based 教学的终点。

1. **只判开放文本，不改选择题的判分。** 两条路并存，规则引擎那条不许被替换。
2. **判分理由必须可回放**：存下 prompt、rubric、模型输出，用户能看到「为什么这么判」。
   做不到可回放就不上——否则勘误台账无从谈起。
3. **判错的代价要先想清楚**：判分影响 Brier 校准分与锚题点亮。
   建议先做成**不计分的第二意见**（「教练还看到了这些」），跑一段时间再谈计分。
4. **离线降级路径**：没有后端时开放题怎么办，要有明确答案。
5. **`validate.py` R19 的工程锁**（内容里出现 `llm` / `judge` 字段即 ERROR）**暂时保留**。
   它挡的是「悄悄把判分接进 LLM」，不是挡这条设计路线本身。
   真要做的时候，连同这条锁一起改，并在本 ADR 补一节说明改成了什么。

## 引用纪律

外部收敛文档一律写全路径 `research/投资教练_收敛_v3.md §2.6`，仓库内文档写文件名 + 节号。
仓库里曾同时存在两份「v3」，`§2.6` 在仓库内会解析到错的那份，这也是这次出错的原因之一。

**其它文档只许引用本 ADR，不许各自复述结论。** 复述是漂移的来源。
