# ADR-0003：抽屉与遮罩必须高于所有全屏层

- 日期：2026-08-26
- 状态：**已裁决**，由 `tools/check_a11y.py` A7 强校验

## 规则

```
顶栏 20 → 底栏 30 → 判卷台 .stage 40 → 幕 .sty 60 → 遮罩 .scrim 79 → 抽屉 .sheet 80 → toast 99
```

**抽屉是从任何层唤起的公共浮层，它必须在最上面。** 新增任何全屏层，
z-index 必须低于 79，并在这里补一行。

## 为什么

曾经 `.sheet` 是 50、`.scrim` 是 49，而幕 `.sty` 是 60——且幕的底是 `night-900`
（完全不透明）、铺满 `inset:0`。于是从幕里唤起的每一个抽屉：

- 质问台（整个产品的旗舰功能）
- 每一处「核这个数字」的溯源抽屉

**DOM 正常、样式正常、事件绑定正常、四道门禁全绿**，而用户点「先质问」看到的是
屏幕纹丝不动。`document.elementFromPoint` 在抽屉的每一个点上返回的都是幕内元素。

这是本仓库第五次撞上同一个模式：**机器门禁只查形状不查真值**。
内容层是出处，设计层是颜色，`check_js` 那次是可执行性，这次是「它到底盖在谁上面」。

## 门禁

`check_a11y.py` A7：对每一个**不透明的全屏层**（`position:fixed` + `inset:0` + 有背景），
断言 `.sheet` / `.scrim` 的 z-index 高于它。

A7 第一版只看选择器的第一条匹配规则，于是被 `.stage,.sty{left:96px}` 这条桌面规则
骗过去、把 `.sty` 静默跳过了——**正是它要抓的那一个**。现在扫全部规则并自查覆盖数：
校验到的全屏层少于 2 个即 ERROR，因为那说明选择器没匹配上，门禁等于没生效。
