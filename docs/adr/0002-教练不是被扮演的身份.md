# ADR-0002：教练不是被扮演的身份

- 日期：2026-08-26
- 状态：**已裁决**（owner 原话，见下）
- 取代：`_superseded/产品体验与用户流程.md` §1「教练系统」与 §5「首个动作是选主教练」

## 背景

v0 设计了三个学派人格教练——**账房先生 / 风控官 / 行为教授**——各有姓名、学派、
自我介绍和 `x_identity` 身份卡，首次进入的第一个动作是三选一。

## 裁决

owner 原话（2026-08-26）：

> 这些 LLM 扮演的人显然就不是「帐房先生」这些原来的设定了，**没有这个选项了**。
> 应该是不同的故事里扮演不同的人，然后在用户的阶段性的故事之后有一个用户专属的教练
> 持续更新对用户的画像，并且教练用户，用户可以选择自己的**倾向**，
> 但**不刻板地保留某个模拟的身份**。

于是：

1. **教练只有一个，就是「你的教练」。** 全站不出现教练的人名（`coachName()` 恒返回
   「你的教练」）。它是一个逐步了解你判断习惯的角色，不是任何人的模拟。
2. **用户选的是侧重，不是人物。** 首屏问「你希望教练先盯你哪一面？」，
   三个选项是 `TONES[].k / .d`：多讲数字与出处 / 多讲求证与流程 / 多讲我自己的偏差。
3. **扮演真人的只有一处：幕里的当事人。** `case.json` 的 `cast[0]`（如 Russell A. Kersh），
   而且他们只说原档里逐字有过的话——这是出处纪律，不是角色扮演。
4. `site.json` 的 `x_coaches` **保留**：它是 `style_lines`（语气语料）的数据源。
   数据留着，名字不上屏。同 `site.json` 节点 icon 仍是 emoji 的处理原则：
   内容文件不为 UI 需求 churn。

## 为什么写成 ADR

这条被**重新争论过一次**：一个 session 按裁决移除了人格选择器，另一个 session
在不知情的情况下把「首个动作是选主教练（三个学派有名有介绍）」重新写进了 DESIGN.md §2
并实现了它。两份文档同时存在、都自称现行，代码按后写的那份跑。

**教训**：被 owner 明确裁决过的事，落进 ADR；其它文档只许引用，不许复述。
复述是漂移的来源。

## 保留了什么

DESIGN.md §2 的**信息架构**是对的，保留：一屏一个动作、没选完什么都不显示、
教练在暗岛底部说话而不是做成一个设置面板。被推翻的只是「选的内容是人物」。
