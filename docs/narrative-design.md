# 投资故事的叙事规范

这不是把题目包上一层剧情，而是把每个判断放回真实事件发生的现场。

## 一段故事的节奏

每个决策段落固定经过六步：

1. **现场**：交代时间、地点、身份、手上的材料，以及此刻正在承受的压力。
2. **消化**：只给当前判断必需的原始证据；把长文本折成数字、对照和一句可记住的事实。
3. **问题**：明确这一刻要决定的变量，不问“你觉得好不好”，而问“先验证哪条链”。
4. **行动**：按钮写成角色会做的动作，例如“追回付款方”，而不是抽象的“选择 A”。
5. **后果**：点击后先呈现现场发生了什么，再告诉玩家这个选择留下了哪一个盲区。
6. **画外音**：解释当时为什么这个选择有吸引力、原始材料支持到哪里、还缺什么证据，然后把压力推向下一段。

## 文案规则

- 不在故事外说教。方法必须从人物的处境和动作里长出来。
- 不提前公布正确答案。选择前给事实和约束，选择后给后果和解释。
- 错误选择也要有尊严：说明它为什么合理、它牺牲了什么、下一次应该查什么。
- 一屏只推进一个问题；原档全文、出处和术语放在需要时展开的证据层。
- 结局不只评价对错，还要让玩家能说出“我当时看见了什么、漏掉了什么”。

## 产品交互

故事界面采用渐进披露：先给现场和关键证据，再出现行动；玩家做出选择后，先锁定选择，再展示即时后果，最后才允许进入下一段。这样点击不是答题提交，而是一次可回看的叙事动作。

学习节奏采用“看一段原档 → 做一次判断 → 读后果 → 回忆方法 → 在下一家公司迁移”的交替结构。每个案例都必须把方法带到一个没有见过的新材料里，而不是在题库里重复同一问法。

## 验收标准

一个故事只有同时满足以下条件，才算完成：

- 玩家知道自己是谁，以及为什么此刻必须做决定；
- 每个选项都改变了现场，而不是只改变颜色或分数；
- 选错后能看见具体后果，并知道当时为什么容易选错；
- 原始文件不是装饰，而是能支撑或推翻判断的证据；
- 故事结束后，玩家能把方法带到另一家公司的真实披露中。
